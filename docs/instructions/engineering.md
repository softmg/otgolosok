# Разработка

## Владеет

Язык, качество кода, Git, тесты, секреты и жизненный цикл планов.

## Не владеет

Не задаёт транспортные лимиты, редактуру, публикационные разрешения или допуск MP4.

## ENG-01

README, документация, планы, MR и интерфейс пишутся по-русски. Решения задачи имеют приоритет над локальными требованиями commit/push: явный запрет этих действий обязателен. В разрешённой задаче завершённый этап оформляется атомарным Conventional Commit: тип и scope английские, описание русское; перед commit проходят lint, typecheck и относящиеся тесты, перед завершением разрешённого Git-цикла выполняются push и проверка отсутствия ahead. Новая ветка требует явного запроса владельца. Чужие изменения не включать и не откатывать.

## ENG-02

Нужны production-ready решения; временные обходы и риски явно описываются с предложением исправления. Не добавлять незапрошенную инфраструктуру. Секреты и .env не входят в Git, логи, ответы API, изображения и диагностические пакеты. .gitignore поддерживать для локальных, временных и генерируемых файлов. Ошибка credential store требует сообщения владельцу о локальных коммитах и заблокированном push; обход защиты запрещён.

## ENG-03

Изменение поведения сопровождается содержательными happy/failure/boundary тестами; bugfix начинается с воспроизведения. Не писать тесты, повторяющие реализацию или проверяющие только вызов mock. Для широких изменений запускать полную suite, для документации допустима проверка ссылок. На этой машине тесты идут через /Users/user/.agents/bin/agent-pool test -- <command>. Runtime-сбои обрабатывать на границе ответственности; transient network/5xx/429/timeouts повторять с ограниченным exponential backoff, deterministic 4xx и логические ошибки не повторять.

## ENG-04

Планы находятся в docs/agents/plans/, формат и Status задают процедуры make-plan/implement-plan. На завершении обновлять Status по факту. Наблюдения записывать в docs/agents и регистрировать двумя предложениями в README индекса. Gotchas в AGENTS добавлять только по явному согласованию владельца; утратившие силу удалять. Источником значений дизайн-системы является `src/styles/tokens.css`; при изменении токенов или правил обновлять дизайн-систему. Многострочные сообщения Git передавать корректной shell-строкой или heredoc, не PowerShell @'…'@.
