# Эксплуатация

## Владеет

Toolchain, локальный режим, диагностика и резервные копии.

## Не владеет

Не определяет валидность квитанций и транспортные лимиты; владеет окружением и эксплуатацией.

## OPS-01

Любые изменения на production требуют явного подтверждения владельца. Проверять toolchain через scripts/toolchain.mjs с учётом data/tools/bin: отсутствие ffmpeg/ffprobe в системном PATH не означает отказ (для локального backend e2e-прогона `elevenlabs-published-audio-e2e.test.mjs` требуется `ffmpeg`/`ffprobe` в PATH, включая `../otgolosok-creative/data/tools/bin`). После живой OAuth-проверки слота локальное планирование запускается с --local --plan-only; не инициировать SSH по умолчанию. Массовые OSM-партии запускать только после разнообразного пилота с ручной проверкой фактов и аудио и фиксацией checksum, лицензии модели и ресурсов машины. Диагностика не заменяет квитанции допуска.

## OPS-02

Перед deploy контролировать диск и retention generator-data/ops-backups: около 409 МБ на пакетную операцию входят в tar бэкапа и могут вызвать ENOSPC. Сохранять последние партии согласно эксплуатационному плану. Для backend снимать согласованный backup всего остановленного тома с WAL и аудио либо через `VACUUM INTO`; не копировать живой `jobs.sqlite` отдельно и не применять `docker compose down -v` для обычной остановки. После восстановления старой резервной копии повторить удаление ранее удалённых аккаунтов до возврата сервиса пользователям. Конфигурацию production не подменять локальной при отсутствии серверного файла.
