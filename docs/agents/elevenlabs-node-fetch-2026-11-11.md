# ElevenLabs: восстановление HTTP-клиента 11 ноября 2026

После переноса production запросы к прокси сначала отклонялись: новый адрес сервера отсутствовал в секрете разрешённых источников. Обновление списка восстановило доступ всех пяти ключей; бесплатная проверка списка голосов подтвердила голос «Отголосок2» для каждого аккаунта. Секреты и адреса серверов здесь не сохраняются.

После этого встроенный `fetch` Node 24.20.0 в production возвращал статус 200, пустые заголовки и сжатое Brotli-тело. `listElevenLabsVoices` завершался `TTS_FAILED`; тот же запрос через `node:https` и установленный `undici` 8.11.0 сохранял заголовки, а `undici.fetch` декодировал JSON. Это наблюдение относится к production-окружению: локальный HTTP-сервер и MockAgent не воспроизвели потерю заголовков.

Выложенный Cloudflare Worker сверили с исходником. Его `new Response(upstream.body, upstream)` сохраняет статус и заголовки в реальном Miniflare/workerd с датой совместимости production; изменений Worker не потребовалось.

Исправление ограничено ElevenLabs: чтение голосов, синтез и загрузчик провайдера по умолчанию используют `fetch` установленного `undici`. Явно переданный `fetchImpl` сохранён, общий `globalThis.fetch` приложения не меняется; модель новых записей остаётся `eleven_v4`.

## Проверка

Регрессионный тест перед исправлением падал при обращении к процессному `fetch`. После исправления локальный MockAgent отдаёт Brotli JSON и MP3 с нужным Content-Type; проверяются чтение списка голосов, загрузчик, байты аудио и отсутствие внешних сетевых запросов. Остальные тесты ElevenLabs продолжают проверять внедрённый HTTP-клиент, ошибки, квоты и резервные ключи.

На сервере бесплатное чтение голосов через установленный `undici` прошло для всех пяти ключей; платный синтез для диагностики не запускался.

## Проверенное восстановление сервиса

Основной архив полностью передан и проверен по SHA-256. Целостность SQLite и контрольные суммы 5674 медиафайлов подтверждены; восстановлены данные, статика и граф Valhalla. Перед переходом с архивного backend на текущий исходник сохранены отдельные снимки SQLite, прежний образ оставлен для отката.

HTTPS отвечает 200 по HTTP/1.1 и HTTP/2; адрес с `www` перенаправляет на основной домен. Проверены все 40 доступных по ссылке прогулок, фотографии, MP3 HEAD и Range 206, отсутствие доступа к личному кабинету без входа и реальный маршрут Valhalla. В браузере существующее аудио воспроизводится, счётчик прошёл 54 секунды.

Для чтения файлов Traefik с правами 0600 контейнер запускается с владельцем файлов; ограничения возможностей контейнера сохранены. Скрипт завершения восстановления передаёт проверочный JavaScript через stdin вместо `docker cp` в каталог tmpfs контейнера с файловой системой только для чтения.

Парковочный снимок содержит только Москву; автомобильный режим в Казани требует отдельного индекса. Очереди после запуска не содержали активных заданий, новых попыток платной генерации при восстановлении не обнаружено.

После выкладки исправления backend здоров, предупреждения `TTS_AUTH` исчезли. Штатное чтение голосов через клиент по умолчанию прошло для пяти аккаунтов (22–23 голоса, собственная копия голоса найдена), повторная проверка всех 40 прогулок прошла. Реальный автомобильный запрос вернул 200 с одним парковочным визитом и тремя сегментами; платных запросов для этих проверок не выполняли.

Проверки репозитория: `pnpm lint`, `pnpm typecheck` и `pnpm test` прошли; backend — 1249/1249. Первоначальный полный прогон обнаружил только прежний мусорный Python-кэш в одной из двух копий навыков: два нетрекаемых `.pyc` сохранены вне checkout, повторный прогон зелёный.
