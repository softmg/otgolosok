# Общедоступные прогулки в админке

В `/admin?section=walks` по умолчанию открывается вкладка «По ссылке».
Она показывает аккаунтные прогулки с `visibility = shared` и действующим
`share_token`, включая прогулки служебного пользователя `promo-walks`.
Встроенные прогулки и редактор их глав доступны во вкладке «Редактор глав».

Данные аккаунтных прогулок находятся в базе авторизации, а редакционные главы —
в основной базе сервиса. Поэтому `GET /api/story-admin/walks/shared` читает
`accountStore`, сохраняя общую проверку доступа редактора и `Cache-Control: no-store`.
Имя и почта владельца доступны только в административном ответе; публичный
`/api/story-walks/shared/:token` не раскрывает их.

Параметры списка: `limit` (1–50, по умолчанию 25), `offset`, `q` (название),
`author` (имя или почта), `mode` (`all`, `open`, `loop`). Фильтры применяются
в SQL до пагинации. Поиск кириллицы без учёта регистра реализован функцией SQLite
`walk_search`, поскольку стандартный `lower()` SQLite не обрабатывает русские
буквы. Символы `%` и `_` ищутся буквально. Повреждённый снимок остаётся виден
с предупреждением и не прерывает загрузку всего списка.

Сортировка: время обновления и ID по убыванию. Если после удаления или закрытия
доступа последняя страница исчезла, сервер возвращает последнюю существующую
страницу и её `offset`. Новые изменения между запросами могут сдвигать страницы:
список показывает текущее состояние, а не зафиксированный снимок всей базы.

Копирование использует действующий токен и адрес текущего сайта:
`/walk?share=…`. При отказе Clipboard API появляется поле для ручного копирования.
Ошибки чтения повторяются через существующий `readFetch`; после окончательного
отказа доступна кнопка «Повторить».

При браузерной проверке найдено и исправлено зависание восстановления сессии
админки в React StrictMode: очистка эффекта отменяла запрос, но оставляла флаг
`sessionRestored`. Теперь очистка сбрасывает флаг, а отменённый запрос проверяет
сигнал до изменения состояния. Регрессионный тест воспроизводит двойной запуск
эффектов.

Проверки: тесты хранилища, HTTP-проверка доступа и параметров, компонентные тесты
копирования и ошибок, браузерный сценарий `e2e/shared-walk-admin.spec.ts`.
Браузер использует настоящие локальные маршруты API и временную SQLite-базу;
тестовая сессия редактора изолирована от рабочих аккаунтов.

Полный `pnpm check` 30 сентября 2026 года прошёл: 589 frontend-тестов,
529 backend-тестов, 19 Python-тестов и 12 подтестов, линтеры, проверка типов
и production-сборка. Браузерный сценарий Chromium прошёл на мобильной
и настольной ширине; выкладка на production в эту задачу не входила.
