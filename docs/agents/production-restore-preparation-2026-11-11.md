# Подготовка нового сервера к восстановлению production

11 ноября 2026 года начата подготовка общего сервера для Отголоска и других
проектов. Адрес сервера и секреты в репозиторий не записываются.

## Схема инфраструктуры

Источники конфигурации находятся в локальном проекте
`/Users/fenix007/projects/utils/services`: `deploy-scheme.md`,
`security-hardening.md` и `deploy-scripts/beget-init.sh`. Деплой выполняется
пользователем `services`, который владеет `/srv/sites` и `/srv/traefik` и входит
в группы `docker` и `sudo`. Парольный барьер sudo сохраняется; правила
`NOPASSWD` не добавляются. Членство в `docker` предоставляет административные
полномочия через Docker API.

Общий Traefik использует `tecnativa/docker-socket-proxy:0.3.0`; сокет Docker
монтируется только в прокси. Для каждого приложения нужна отдельная ingress-сеть,
заранее записанная в двух местах Compose Traefik: у сервиса `traefik` и в корневом
`networks` с `external: true`. Базовая сеть `traefik-net` для приложений
не используется. У Отголоска сохраняются каталог
`/srv/sites/otgolosok.softmg.tech` и сеть `otgolosoksoftmgtech-net`.

## Выполненная подготовка ОС

- Ubuntu 26.04.1 LTS, amd64, 2 vCPU, около 2 ГиБ RAM и диск 40 ГБ.
- Docker Engine 29.9.3, Compose 5.7.0 и Buildx 0.38.1 установлены из официального
  репозитория Docker для `resolute`; подпись пакетов проверяется отдельным ключом.
- Установлены утилиты для переноса и проверки данных, включая `rsync`, `jq`
  и `sqlite3`.
- Создан swap 2 ГиБ с правами `0600` и записью в `/etc/fstab`.
- Docker-логи ограничены: `json-file`, `max-size=10m`, `max-file=3`.
- Для новых Docker-сетей настроен пул `10.201.0.0/16` с подсетями `/24`.
  Пересечений с маршрутами сервера на момент настройки не найдено. Перед
  подключением VPN совместимость адресов нужно проверить повторно.
- Подготовлены каталоги `/srv/sites`, `/srv/traefik` и закрытый каталог
  `/srv/otgolosok-restore` для входящих архивов.
- UFW включён: входящие соединения запрещены, разрешены TCP 22, 80 и 443.
  Доступ к существующему Zabbix на 10050 сохранён только для адресов провайдера
  из его конфигурации; агент не удалялся.
- Для Docker установлены `/usr/local/sbin/docker-user-fw.sh` и
  `docker-user-fw.service`: входящий трафик в контейнеры допускается только
  через исходные хостовые TCP-порты 80 и 443. Правила используют
  `conntrack --ctorigdstport`, применяются для IPv4 и IPv6 и восстанавливаются
  после перезапуска Docker. UFW сам по себе опубликованные Docker-порты
  не закрывает.

## Проверки и ограничения

Проверены запуск Docker, Compose и Buildx, выполнение `hello-world`,
синтаксис конфигурации Docker и unit firewall, а также сохранность правил
после перезапуска Docker. Внешняя проверка временного контейнера подтвердила
HTTP 200 на порту 80 и недоступность публикации `9999:80`; после проверки
контейнер удалён. Правила IPv6 проверены по конфигурации; у сервера на момент
настройки нет публичного IPv6, внешняя проба IPv6 не выполнялась.

Вход `services` проверен отдельной SSH-сессией существующим ключом
`~/.ssh/id_ed25519_vps_services`. Ключ защищён парольной фразой; для проверки
его разблокировали через защищённую форму и отдельный SSH-agent с ограничением
времени хранения ключа в один час. Проверены доступ к Docker без sudo, запуск
контейнера и запись в рабочие каталоги.

После успешного входа добавлен `/etc/ssh/sshd_config.d/01-services-hardening.conf`:
SSH только по ключам, парольная и интерактивная аутентификация отключены,
`PermitRootLogin no`. Проверены `sshd -t`, итоговые параметры `sshd -T` и ещё
одна независимая SSH-сессия `services` после применения настроек. `sudo`
требует пароль; правило `NOPASSWD` не добавлялось.

Полный `pnpm check` прошёл: lint, TypeScript, JavaScript/TypeScript-тесты,
Python-проверки и статическая сборка. Для `uv` задан отдельный `UV_CACHE_DIR`
в хранилище потока: обычный пользовательский кеш недоступен файловой песочнице.

Документация `services` рекомендует минимум 4 ГБ RAM для нескольких приложений.
Текущие 2 ГиБ оставляют небольшой запас с учётом backend и Valhalla Отголоска;
перед массовым переносом следует увеличить память. Swap помогает пережить пик,
но не заменяет оперативную память. Сборки образов и пересборку графа маршрутов
не следует запускать одновременно.

## Что требуется для восстановления

Штатный `backups/generator-*/generator.tar.gz` содержит `generator-data`,
`generator-backend`, `generator-compose.yml`, `.generator.env`,
`docker-compose.yml` и `nginx.conf`. В него не входят `dist`, `valhalla-data`,
общий `/srv/traefik` и образ генератора. Нужны отдельные копии статики,
московско-казанского графа маршрутов и конфигурации Traefik с сертификатами;
образ можно собрать из сохранённых исходников backend.

Расположение и дата выбранного бэкапа пока не определены. Общий Traefik,
приложения и базы не восстановлены, DNS не переключался. Существующие общие
`.env` проекта `services` и `.env.ops` Отголоска на новый сервер не перенаправлялись.
До переключения нужно проверить целостность SQLite, авторизацию, прогулки,
аудиофайлы, маршрутизацию и TLS через прямое разрешение домена на новый IP.
Для прокси ElevenLabs потребуется разрешить новый исходящий IP.

Режим HTTP/2-only из старого production-runbook не переносить: с 14 октября
production поддерживает HTTP/1.1 и HTTP/2; см.
[актуальное уточнение](production-tls-http2.md).
