# Крытые участки маршрута (подземные переходы и арки)

Маршрут прогулки рисуется пунктиром там, где он идёт под землёй или сквозь здание. Данные — диапазоны вершин `route.tunnels: [[a, b], …]` в `WalkDocument` (все отрезки `a..b` линии `route.geometry` крытые); в `Route` для страницы прогулки это `walk.path.tunnels`. Правила формата — `validTunnels` в `backend/walk-document.mjs`: не больше 500 пар целых `0 ≤ a < b ≤ длина − 1`, по возрастанию, без пересечений и касаний. Ключа нет, если крытых участков нет или их не искали.

## Откуда берутся

Планировщик (`backend/walks.mjs`) после выбора итогового маршрута спрашивает Valhalla `POST /trace_attributes` по каждому участку между остановками (`traceTunnels`). Кандидаты при подборе маршрута не проверяются, только итоговый. Ограничения:

- Запрос идёт, только если до общего срока плана (12 с) осталось не меньше 2 с; сам поиск ограничен 1,5 с (`TRACE_TIMEOUT_MS`).
- Всё или ничего: любой сбой (сеть, не 2xx, `error_code`, битый JSON, ответ больше 1 МБ, тайм-аут, индекс за пределами формы) даёт маршрут без `tunnels`. Частичный набор показал бы часть переходов сплошной линией без возможности это заметить.
- Повторов нет: данные косметические, бюджет плана общий с маршрутизацией, а следующее построение маршрута получит новую попытку.
- Коды ошибок `WALK_*` поиск не меняет.

Переключатель — `WALK_TRACE_URL`, полный адрес `/trace_attributes`. В `compose.yaml` по умолчанию `http://valhalla:8002/trace_attributes`, причём подстановка `${WALK_TRACE_URL-…}` без двоеточия: пустое значение в production `.env` выключает поиск без выкладки кода, а `:-` подставил бы адрес по умолчанию и выключить было бы нельзя. Адрес не http(s) или с логином/паролем считается невыставленным.

Промо-прогулки и исследовательский планировщик получают крытые участки тем же путём; для этого `backend/walk-plan-document.mjs` переносит `plan.tunnels` в документ.

## Что выяснено о Valhalla (локальный 3.8.3, 2 октября 2026)

- `edge.tunnel: true` стоит у подземных переходов (Пушкинская под Тверской, Маяковская под Садовым) и у `tunnel=building_passage` — арок сквозь здания (way 39950039, Георгиевский переулок). У переходов дополнительно `levels: [[-1,-1]]`, у арок `levels` нет. Пунктиром рисуются оба вида: сверху не видно ни того, ни другого.
- `shape_match: "edge_walk"` падает с HTTP 400 `error_code: 443` на участке, который начинается разворотом у остановки (частый случай с остановками `type: "break"`). Используется `walk_or_snap`.
- `walk_or_snap`/`map_snap` возвращают свою форму (76 точек на 78 входных), поэтому `begin_shape_index`/`end_shape_index` не индексируют нашу линию. Сопоставление геометрическое: отрезок участка крытый, если оба его конца не дальше 3 м от крытого куска возвращённой формы. Затем индексы переводятся в общие (участок `j` начинается с последней вершины предыдущего) и соседние диапазоны склеиваются.
- Время: около 7 мс на участок, около 67 мс на целый план.

Проверка планировщика на локальном Valhalla (`127.0.0.1:8002`):

| Откуда → куда | `tunnels` |
| --- | --- |
| 55.7652,37.6075 → 55.7672,37.6037 (Пушкинская) | `[[0,1],[5,6],[7,11]]` |
| 55.7702,37.5965 → 55.7693,37.5930 (Маяковская) | `[[10,19]]` |
| 55.7655,37.6068 → 55.7645,37.6040 | `[[10,19]]` |
| 55.7660,37.6060 → 55.7668,37.6030 | нет: крытых участков на этом маршруте не нашлось |

## Встроенная каталожная прогулка

`msk-kozhevniki-zindel-short` размечена один раз: вся `walk.path.coordinates` передана одним участком в `traceTunnels` с `fetchImpl: fetch, traceUrl: "http://127.0.0.1:8002/trace_attributes"`. Результат — `[[29,30]]` (31 вершина), записан в `walk.path.tunnels` файла `public/data/routes/paveletskaya.json`. `backend/builtin-routes.mjs` генерируется из него командой `node scripts/build-walk-catalog.mjs`, руками его не править. `backend/walk-catalog.mjs` передаёт `path.tunnels` в `route.tunnels`.

Старые прогулки — сохранённые в аккаунтах, по ссылкам и в браузерах — остаются со сплошной линией, пока их маршрут не перестроят. Дозаполнения базы нет.

## Порядок выкладки

Frontend (валидаторы и отрисовка) выкладывается вместе с backend или раньше него. Офлайн-оболочка из старого кеша отвергает документы с новым ключом `tunnels`, пока не обновится; это само проходит при следующей загрузке по сети, есть и `/update.html` (та же опасность, что в [boulevard-ring-walk-2026-09-30.md](boulevard-ring-walk-2026-09-30.md)).
