# TLS и HTTP/2 на production

**С 14 октября 2026 года HTTP/1.1 снова обслуживается.** В ALPN объявлены `h2` и `http/1.1` (браузеры по-прежнему получают HTTP/2), middleware `otgolosok-h2-only` снят с маршрутов сайта и генератора. Режим «только HTTP/2» отвечал 505 любому клиенту HTTP/1.1. Из-за этого сервер проверки Google Search Console не мог подтвердить сайт («Не удалось найти ваш сайт»), а роботы на HTTP/1.1 (судя по всему, и робот Яндекса) не видели страниц. Определение middleware и плагин на сервере оставлены неиспользуемыми: удалить определение раньше меток значило бы сломать маршруты, а плагин можно убрать при следующем обслуживании Traefik вместе с `experimental.localPlugins`. `scripts/verify-production-tls.sh` теперь требует для `/`, `/api/story-service` и `/sitemap.xml` ответ `200 2` по HTTP/2 и `200 1.1` по HTTP/1.1, а также отсутствие `h2-only` в метках.

Изменение 14.10 сделали прямо на VPS, без правки репозиториев. Поэтому `local-ops.sh` 15.10 при деплое статики снова повесил `h2only` на маршрут сайта: до 17.10 страницы по HTTP/1.1 отдавали 505, а API и sitemap — 200. В инфраструктурном каталоге тогда же не оказалось и серверных правок `otgolosok-generator-compose.yml` (маршруты `/place/`, `/places`, `/sitemap.xml`, ротация логов, `tile_urls` для Москвы и Казани). 17.10 оба репозитория приведены к серверу, а `scripts/verify-production-tls.sh` проверяет, что ни у одного маршрута нет `h2only` и что `/`, `/api/` и `/sitemap.xml` отвечают 200 по HTTP/1.1. Правки конфигурации на сервере сначала вносите в репозиторий, иначе следующий деплой их откатит.

## История: только HTTP/2 (28.09–14.10)

28 сентября 2026 года для `otgolosok.online` включены TLS 1.2 и 1.3. В TLS ALPN объявлен только `h2`. Traefik 2.11 при отсутствии общего ALPN всё равно принимает HTTP/1.1, поэтому для маршрутов сайта и `/api/` подключён локальный middleware `h2only`, который отвечает 505 до передачи запроса приложению. На порту 80 HTTP/1.1 остаётся для перенаправления на HTTPS и проверки Let's Encrypt HTTP-01.

Настройки домена лежат на VPS в `/srv/traefik/otgolosok-tls.yml`, исходник middleware — в `/srv/traefik/plugins-local/src/github.com/softmg/h2only/`. Версионированный источник — [ops/production/traefik](../../ops/production/traefik/README.md); скрипт `scripts/verify-production-tls.sh` сравнивает его с VPS и проверяет маршруты. Файл TLS подхватывается file provider, исходник middleware — через `experimental.localPlugins`. Оба смонтированы в контейнер Traefik. Маршруты статического сайта и генератора ссылаются на `otgolosok@file`; для повторного деплоя метка закреплена в `local-ops.sh` и `otgolosok-generator-compose.yml` инфраструктурного каталога.

Перед изменением созданы резервные копии конфигураций в `/srv/sites/otgolosok.softmg.tech/backups/tls-20260928T152425Z/`. Проверки с прямым подключением к адресу production-VPS: TLS 1.2 + HTTP/2 вернул 200 для сайта и API; TLS 1.3 согласовал `h2`; TLS 1.1 отвергнут; HTTP/1.1 вернул 505 для сайта и API. Генератор после перезапуска стал healthy. Другой домен на общем Traefik сохранил HTTP/1.1.

При следующем обновлении Traefik нужно проверить совместимость локального middleware и повторить протокольные пробы. У общего Traefik уже есть отдельная ошибка продления сертификата `brief.softmg.tech` из-за NXDOMAIN; она не связана с этим изменением и требует восстановления DNS-записи или удаления старого маршрута.

29 сентября 2026 года проверка попала на параллельный деплой генератора: во время резервного копирования контейнер штатно останавливается, а `/api/` временно возвращает 404 через статический маршрут. Первый осмотр процессов не захватил `bash -s` деплоя, поэтому контейнер был кратко запущен вручную, затем деплой остановил его повторно и завершился штатным запуском. После завершения генератор healthy, API возвращает 200, проверка TLS и HTTP/2 проходит. Скрипт проверки требует healthy состояния генератора; запускать его следует после завершения деплоя.

Остановка API на время архивации почти гигабайта данных — риск текущего скрипта деплоя. Надлежащее исправление: делать согласованный снимок SQLite и файлов без остановки действующего контейнера, поднимать новую версию параллельно и переключать маршрут после её readiness-проверки.
