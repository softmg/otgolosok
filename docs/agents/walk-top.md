# Топ прогулок и учёт запусков

Вкладка «Топ прогулок» на `/history` показывает до 20 прогулок: каталожные, промо и
пользовательские с доступом «Доступно всем», одобренные редакцией. Список отдаёт
`GET /api/top-walks` (`backend/walk-top.mjs`), он считается на каждый запрос без кеша.

## Формула

`score = ((C × m) + Σоценок) / (C + n) × ln(1 + запуски)`, где `n` — число опубликованных
оценок прогулки, `m` — средняя всех опубликованных оценок (4,0, пока оценок нет), `C = 5`.
Прогулка без запусков получает 0 и опускается вниз. При равенстве порядок решают запуски,
затем число оценок, затем время попадания в топ (новее выше), затем ID. Запуски считаются
за всё время; суточные агрегаты позволяют позже ввести окно без потери данных.

Карточка топа: название, рейтинг (средняя округляется до двух знаков, как в сводке отзывов),
время, длина и число историй. Число запусков и автор в API не возвращаются. Прогулка с
повреждённым снимком или без маршрута пропускается, и топ добирается следующими.

## Модерация

Открытая всем прогулка сразу работает по ссылке, а в топ попадает после одобрения в
админке (вкладка «Пользовательские»). Состояния: `pending` → `approved` | `hidden`.
Одобренная прогулка возвращается на проверку, только если изменились модерируемые тексты:
название, описание, адреса старта, финиша и остановок, `transition` и `nextHint`
(SHA-256 по NFC-нормализованным строкам, `backend/walk-listing.mjs`). Перестроение
маршрута без смены текстов одобрение сохраняет. Скрытая редакцией прогулка остаётся
скрытой при любых правках владельца; вернуть её может только редактор. Действия
редактора принимают `revision` и отвечают 409, если прогулка успела измениться.

## Учёт запусков

Запуск — нажатие «Начать прогулку» на прогулке, открытой через `?catalog=` или `?share=`
(`POST /api/story-walks/:slug/launches` и `…/shared/:token/launches`, пустое тело `{}`).
Своя прогулка (`?id=`), локальная (`?local=`) и запуски владельца не считаются. Клиент
шлёт отчёт один раз за открытие страницы, сбой учёта прогулку не ломает.

Зритель — аккаунт (с CSRF) или гость по ключу устройства `X-Review-Key`. Один зритель
даёт не больше одного запуска на прогулку в московские сутки (UTC+3 без перехода).

Редактор видит запуски за всё время в админке, в разделе «Прогулки»: в списке «Пользовательские»
(`launches`, по умолчанию 0) и в каталоге «Редактор глав». Если базы аккаунтов нет, в каталоге
приходит `launches: null` и показывается «Нет данных». Публичный API запуски не отдаёт.

Ограничения:
- 60 отчётов в час на пользователя или IP — сверх лимита 429 с `Retry-After`;
- 30 засчитанных запусков одной прогулки в сутки с одного IP — сверх лимита тихий
  `{counted:false}`.

Второй лимит не даёт накрутить прогулку сменой ключа устройства. Компромисс: за CGNAT
(мобильные операторы, общий Wi-Fi) больше 30 настоящих зрителей с одного адреса за сутки
не засчитываются. Это сознательный выбор в пользу защиты от накрутки.

## Приватность

Зритель хранится только как SHA-256 от `user:<id>` или `device:<ключ>`. Сырой ключ не
пишется в базу и логи. Отметки дедупликации (`walk_launch_marks`) удаляются через двое
суток (чистка не чаще раза в час), агрегаты (`walk_launch_days`) не содержат зрителей.
Таблицы без внешних ключей, как у отзывов: после удаления прогулки агрегаты остаются
сиротами и топом игнорируются.
