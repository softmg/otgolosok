# Заведения рядом с прогулкой

Сводная заметка по фазам 1–7 [плана](plans/2026-10-04-food-along-walk.md). Описывает текущий код и локальные замеры на 04.10.2026; выкладка не выполнялась и требует подтверждения пользователя.

## Данные и сопоставление тегов

Индекс строится только из PBF Москвы BBBike (ODbL-1.0), того же снимка, что используется для маршрутизации и адресного индекса. `scripts/build-osm-food-index.py` использует osmium и образец `build-osm-address-index.py`: временный SQLite рядом с целевым файлом, `PRAGMA integrity_check`, атомарный `os.replace`. Ошибка сборки и пустой результат сохраняют прежний индекс. Заведения не добавляются в каталог историй и очередь генерации.

| Теги OSM | `kind` | Группа интерфейса |
|---|---|---|
| `amenity=cafe`, элемент `coffee_shop` в списке `cuisine` через `;` | `coffee` | Кофейни |
| Остальные `amenity=cafe` | `cafe` | Кафе и рестораны |
| `amenity=restaurant` | `restaurant` | Кафе и рестораны |
| `amenity=fast_food`, `food_court`, `ice_cream` | `fast_food` | Перекус |
| `shop=bakery`, `pastry` | `bakery` | Перекус |
| `amenity=bar`, `pub`, `biergarten` | `bar` | Бары и пабы |

`shop=coffee` сам по себе не включается: магазин зерна не означает место для перекуса. Исключаются объекты без имени, `access=private|no`, `opening_hours=closed|off`, объекты с префиксами `disused:`, `abandoned:`, `was:`. Дубли node внутри контура с одинаковыми именем и типом удаляются в пользу node. Для way/relation вычисляется центроид, а если он вне поверхности — внутренняя репрезентативная точка; неполная геометрия пропускается и учитывается в отчёте. Точка обозначает заведение, точный вход не гарантируется.

Таблица `places` отдельного food-индекса содержит `id,kind,name,lat,lon,address,opening_hours,cuisine,website,phone`. Координаты округлены до пяти знаков. Адрес собирается из адресных тегов, сайт допускает только http/https без учётных данных; незаполненные поля — `null`. Идентификаторы имеют вид `osm:node:…`, `osm:way:…`, `osm:relation:…`. Метаданные `meta`: версия формата 1, SHA-256 PBF, дата последней правки включённых объектов, дата сборки, количества по категориям, источник, лицензия, атрибуция, пропуски и дубли.

### Снимок и размер ячейки

Повторный замер 04.10.2026 подтвердил снимок SHA-256 `e5dd91709a7a5786afb59b67ba52cecc829adc466a877bd610af5b4aeb1cf8cc`, дата источника `2026-10-02T21:21:10+00:00`. Всего **13 294** заведения: coffee 1 881, cafe 3 083, restaurant 2 697, fast_food 3 878, bakery 590, bar 1 165. Часы есть у **7 685 (57,8%)**; пропущено по геометрии 124 объекта, удалён один дубль. ## API и обновление индекса

`backend/food-places.mjs` открывает `DATA_DIR/osm-food.sqlite` только для чтения. Проверяет формат, дату, атрибуцию, колонки и координаты; отсутствующий файл отключает функцию, повреждённый/несовместимый даёт `FOOD_INDEX_INVALID` при запуске без раскрытия пути или содержимого. Все занятые ячейки сериализуются при старте, после чего SQLite сразу закрывается; `close()` возвращённого снимка не удерживает соединение. Замена файла начинает действовать после перезапуска генератора.

- `GET`/`HEAD /api/food/cells` → `{version:1,cellSize:0.05,sourceEditedAt,attribution,cells:[{lat,lon,count,etag}]}`.
- `GET`/`HEAD /api/food/cells/{latKey}/{lonKey}` → `{lat,lon,places:[...]}`; поля клиента — `id,kind,name,lat,lon,address,openingHours,cuisine,website,phone`, сортировка по id.
- Ключ — `floor(coord * 20)`, широта `[-1800,1799]`, долгота `[-3600,3599]`; +90/+180 попадают в последнюю ячейку. Умножение избегает ошибок деления на границах сетки.
- Query-строки (даже пустой `?`), `-0`, ведущие нули, дроби, неверный путь и выход за диапазон дают 400, в том числе без индекса.
- Без индекса — 503 `{"error":"FOOD_INDEX_UNAVAILABLE"}`, `Cache-Control: no-store`, без ETag; основной сервер продолжает работать.

Используется `http-cache.mjs`: ETag, 304, br/gzip, `Vary: Accept-Encoding`, `no-cache`. ETag ячейки в манифесте совпадает с HTTP-заголовком без внешних кавычек. Кеш пустых ячеек ограничен 128 записями. Правило `/api/food/` в nginx сохраняет заголовки backend и не вводит отдельный proxy-кеш; compose уже подключает нужный DATA_DIR.

Ручное обновление:

```sh
make osm-food PBF=/path/to/Moscow.osm.pbf
# Для Python из окружения uv:
make osm-food PBF=/path/to/Moscow.osm.pbf OSM_PYTHON="$(uv run which python)"
```

PBF должен совпадать со снимком, используемым для Valhalla; Python-окружение должно содержать зависимости проекта, включая osmium. Результат — `backend/data/osm-food.sqlite`, исключённый из git. Проверить отчёт сборки, SHA-256 источника, дату, число мест и целостность. После разрешения выкладки загрузить файл под временным именем **на той же файловой системе** и атомарно переименовать в `DATA_DIR/osm-food.sqlite` рядом с `osm-addresses.sqlite`; затем перезапустить генератор. До перезапуска обслуживается прежний снимок. После — проверить локально доступный манифест, центральную ячейку и интерфейс прогулки. Адреса серверов и детали доступа здесь намеренно не фиксируются; фаза 7 не выполняет эти операции.

## Клиент: загрузка и близость к маршруту

`src/lib/geo/cell-store.ts` — общий загрузчик карты и еды: память → Cache Storage → условный запрос, немедленная выдача старого кеша, фоновая ревалидация, объединение запросов, дедупликация по id, не более четырёх параллельных загрузок. `food-cells.ts` использует отдельный `food-cells-v1`, строгую проверку манифеста и всех мест в ячейке; ячейки вне манифеста не запрашиваются. Публичные методы: `loadManifest`, `loadKeys`, `loadArea`, подписка, стабильный `snapshot`, `retry`, `revalidate`. Пустой массив не означает успех: состояния `manifestStatus`/`cellStatus` и `unavailable` различают загрузку, ошибку и 503.

Сеть, 429 и 5xx кроме food-503: максимум три попытки, паузы 500/1000 мс с jitter, тайм-аут 20 секунд на попытку. Отмена прерывает запрос и паузу. Детерминированные 4xx и food-503 не повторяются автоматически; 503 скрывает функцию.

`route-proximity.ts` проецирует заведение на ближайший отрезок в локальной равнопромежуточной проекции и возвращает `distanceM`, накопленную длину `alongM` и вершину. `placesAlongRoute` оставляет места в **150 м по прямой** и сортирует по `alongM`, затем id. В петле выбирается первый локальный минимум в пределах лучшей дистанции +15 м и заданного радиуса. `cellsForRoute` даёт консервативный набор ячеек с буфером, включая соседей на границах. Минуты обхода не обещаются.

BBox отсекает далёкие места, метровые бакеты ограничивают проверяемые отрезки. Тест маршрута 8 100 м / 12 000 вершин и 2 000 заведений (половина в 60 м, половина в 600 м) делает **1 095 290** проверок вместо **23 998 000** (4,56%); порог теста — число пар менее 10%, без нестабильного порога времени. Результат на извилистой линии сравнивается с полным перебором.

## Часы работы

Разбор своего ограниченного недельного подмножества, без зависимости opening_hours.js:

- `24/7`; дни, списки и диапазоны (`Mo-Fr,Su`), включая диапазон через воскресенье.
- `HH:MM-HH:MM`, несколько интервалов через запятую, перерывы, час без ведущего нуля, конец `24:00`, ночь и Su→Mo; `00:00-00:00` означает сутки. Другие одинаковые начало и конец неизвестны.
- Правила через `;`: последнее заменяет выбранные дни, включая унаследованный ночной хвост. Поддержана встречающаяся запятая перед новым правилом с днями и пробелы после запятой в списке дней.
- `off`/`closed`; самостоятельное `PH off` игнорируется с оговоркой «В праздники часы работы могут отличаться».

Начало интервала включено, конец исключён: ровно в 22:00 интервал до 22:00 уже закрыт. Месяцы, недели, sunrise/sunset, комментарии, составные селекторы PH и произвольный текст дают `unknown` для всей строки. Календаря праздников нет. Время всегда вычисляется через `Intl.DateTimeFormat` в **Europe/Moscow**, независимо от пояса устройства. `opensAt` — `{day,time,daysAhead}`, ближайшее открытие ищется в пределах семи суток. `unknown` отображается как «Часы не указаны»; исходная строка доступна в карточке.

На текущем индексе подтверждено **7 566 / 7 685 (98,45%)** распознанных непустых строк; 119 (1,55%) неизвестны. Это доля среди заведений с часами, а не среди всех заведений. До простых расширений грамматики было 7 411 / 7 685 (96,43%). Замер взвешен по числу заведений, а не уникальных правил. Частые неизвестные значения:

| `Mo-Su,PH 12:00-24:00` | 6 |
| `Mo-Su,PH 10:00-22:00` | 5 |
| `PH,Mo-Su 10:00-23:00` | 5 |
| `PH,Mo-Su 10:00-22:00` | 4 |
| `Mo-Su,PH 11:00-23:00` | 3 |
| `12-00 до 21-00` | 2 |
| `Mo-Su,PH 08:00-22:00` | 2 |
| `Mo-Su,PH 09:00-21:00` | 2 |

## Прогулка и карта «Рядом»

В WalkSession кнопка «Поесть рядом» появляется при доступном манифесте и геометрии. Ячейки загружаются при открытии ящика. До старта места идут по маршруту и группируются по ближайшей остановке вдоль линии; во время прогулки видны «Впереди», пройденные свёрнуты в «Позади». Граница совпадает с начальной вершиной текущего highlightedLeg из `routeLegCuts`. Сам WalkSession использует старую модель Route (`route.walk.path.coordinates`); режим документа передаёт WalkView, для старых вызовов кольцо определяется по совпадающим старту и финишу.

Метки food меньше меток историй, имеют цель 44×44, не кластеризуются с историями, доступны с клавиатуры. Видны только при открытом ящике; камера вписывает выбранное заведение и проекцию на маршрут, сохраняя подсветку участка. OSM-текст не вставляется в HTML Leaflet. Аудио, геопозиция, wake lock и стадии approach/stop продолжают работать. Кнопка в футере — круглый значок без подписи, того же размера, что «Назад» (aria-label сохраняется): панель не шире 430 px, и подпись в 150 px рядом с «Назад» и «Продолжить прогулку» не помещалась ни на одном экране — основная кнопка переносилась на две строки. Основная кнопка не переносит подпись: если ей мало места, она встаёт отдельной строкой (`flex-wrap`), а на панели уже 360 px теряет декоративную стрелку. Проверка — `e2e/walk-food.spec.ts`, «футер прогулки не переносит подпись…»; ящик сжимается и прокручивается первым, футер с основным действием остаётся видимым.

Общая `FoodCard` показывает категорию, переведённые известные значения cuisine, часы, оговорку, исходное правило под раскрытием, адрес, безопасные «Сайт» (http/https) и «Позвонить» (очищенные цифры с допустимым начальным плюсом). Неизвестная кухня и недопустимые ссылки скрываются. Разобранные часы, включая неизвестные, кешируются по строке весь срок экрана; статусы обновляются на границах минут. В списке и карточке видны дата источника, предупреждение об актуальности часов и атрибуция из манифеста. Реальный индекс передаёт `© OpenStreetMap contributors`; тестовые данные — русское `© участники OpenStreetMap`, интерфейс сохраняет исходную атрибуцию.

На обычном экране «Рядом» переключатель «Еда» сохраняется в `otgolosok:around:food:v1` через защищённый localStorage; отказ хранилища не мешает текущему переключению. Ячейки загружаются при включении и масштабе **≥15**, иначе показано «Приблизьте карту, чтобы увидеть заведения». Выборка — `required`, область с запасом полшага масштаба (примерно ×1,41 по осям), а не большой `buffered` историй. При >300 местах показываются ближайшие к центру **300**, равенство разрешается по id. Food-pane 590 ниже story-pane 600 даже при выборе; префикс `food:` исключает конфликты id. Карточка переиспользует FoodCard и показывает расстояние по прямой от известной геопозиции. Выбор истории, дома и заведения взаимоисключающий. Конструктор прогулки food API не загружает.

Четыре глифа Pinhead CC0: кофе, вилка/нож, бургер, бокал; точные пути из `MAP_ICONS`, цвета из токенов `--muted`, `--teal`, `--map-orange`, `--map-green`. Контраст белого глифа ≥4,5:1 проверен тестом. Новые стили — CSS Modules и токены.

## Офлайн-копия

`saveWalkOffline` после аудио скачивает манифест и занятые ячейки маршрута с буфером. Проверяются структура, ключ, ETag и количество мест; смена снимка во время скачивания отменяет всю необязательную food-копию. В `walk-packs-v1` она принадлежит стадии: `<stage>/food/manifest.json` и `<stage>/food/<lat>/<lon>`. Необязательное поле `OfflineWalkManifest.food` содержит дату, атрибуцию и `{key,etag,bytes}`; старые манифесты версии 1 остаются читаемыми.

UTF-8 байты манифеста и ячеек учитываются в оставшемся после аудио бюджете **MAX_PACK_BYTES = 60 МиБ** и ограничены дополнительным **OFFLINE_FOOD_MAX_BYTES = 4 МиБ**. Ровно на границе копия допустима. Превышение лимита, сеть, повреждение ячейки или отказ записи удаляют всю food-часть, сохраняя прогулку. При доступной функции UI пишет «Заведения не сохранены»; 503, отсутствие геометрии или неподтверждённый манифест не вызывают предупреждения.

**Засев хранилища происходит только при открытии прогулки из копии:** `loadOfflineWalk(ref, cache, { seedFood: true })`. По умолчанию `seedFood: false`; проверка наличия/статуса копии и `isWalkOffline` не меняют глобальное хранилище. `walk-loader.ts` явно включает засев на fallback. Перед ним проверяются все ячейки и размер; повреждённая optional-часть не препятствует открытию прогулки. Пакет **не откатывает более свежий манифест** в памяти: `seedOfflineFood` сравнивает `sourceEditedAt`. Засев не пишет в `food-cells-v1` и не присваивает сетевому манифесту ETag пакета; после восстановления сети обычная ревалидация обновляет ячейки.

Удаление, обновление и выход из аккаунта удаляют food вместе с владеющей стадией, не затрагивая общее аудио других копий. Ячейки в памяти сохраняют обычную семантику загрузчика.

Старый TourExperience использует отдельный `published-route-cache.ts`: координаты `[lon,lat]` преобразуются в объекты, food-снимок встроен в один атомарно заменяемый ответ маршрута и засевается на fallback. В этом пути food ограничен отдельными **4 МиБ**, без вычитания уже кешируемого аудио; для одной аудиозаписи действует прежний лимит 25 000 000 байт. Утверждение промежуточной заметки об общем бюджете этого пути не соответствовало коду. Отдельных осиротевших food-ячеек здесь нет.

Dev e2e открывает сохранённую прогулку через роутер после `context.setOffline(true)`, без открытия списка до сохранения и после удаления `food-cells-v1`. Полную перезагрузку без сети проверяли отдельно на локальной статической production-сборке с настоящим service worker (`FOOD_OFFLINE_PRODUCTION=1`); dev service worker не регистрирует.

## Сверка фазы 0 и ограничения

## Заведение как остановка прогулки (05.10.2026)

Плюсик у заведения в «Поесть рядом» и кнопка «Добавить в прогулку» в его карточке делают заведение остановкой без истории. Остановка встаёт между соседними точками по ходу маршрута: предыдущая остановка → заведение → следующая. Код: `src/features/walks/food-stop.ts` (место вставки и сшивка), `add-food-stop.ts` (запрос и сохранение).

- **Путь.** Заменяется только участок между соседними остановками. В `POST /api/walk-plan` уходит `start` = вершина маршрута у предыдущей остановки, `stops` = [заведение], `destination` = вершина у следующей, `minutes: 90`. Бюджет 90 нужен, чтобы проверка длительности планировщика не мешала короткому участку. Остальная геометрия, её туннели и другие остановки не меняются: туннели участка обрезаются по краям, туннели нового пути сдвигаются. Длина и время пересчитываются пропорционально заменённой доле линии. Сшивка с разрывом больше 10 м отклоняется, как и в backend. Заведение ближе 5 м к краю участка добавляется без нового пути. Участок без длины строится петлёй (`mode: "loop"`).
- **Документ.** У предыдущей остановки очищаются `transition`/`nextHint`: подсказка вела мимо заведения. Прогулка длиннее `minutes` переходит на следующую длительность конструктора (30/60/90), иначе её нельзя перестроить в конструкторе. Предел — 90 минут, 8 100 м, 40 остановок. Уже добавленное заведение узнаётся по точным координатам остановки.
- **Сохранение.** Своя прогулка сохраняется на месте: на устройстве — `saveLocalWalk` с ревизией, в кабинете — `PATCH /api/me/walks/:id` с `revision`. Каталожная прогулка и прогулка по ссылке не меняются: создаётся копия, при входе в аккаунт — в кабинет (`POST /api/me/walks`), без входа — на устройство. Направление и место в аудио переносятся на копию. Страница переходит на адрес копии через `history.replaceState` без перемонтирования (`WalkScreen.keys`/`mount`), поэтому начатая прогулка продолжается.
- **Во время прогулки.** Плюсик есть только у заведений впереди. Человек остаётся у той остановки, у которой стоит или к которой идёт. Исключение — заведение на текущем участке: оно становится следующей целью (`followChapter` в `walk-plan.tsx`), а триггер прибытия сбрасывается.
- **Отказы.** Ответы 400/404 планировщика показываются как «Не получилось проложить пешеходный путь к этому заведению». 429/5xx и сетевые ошибки повторяются в `loadJson`, затем показывается сообщение сервера. Без сети добавить заведение нельзя. После добавления офлайн-копия своей прогулки устаревает, пока её не сохранят заново.
- **Карта.** Выбранное заведение увеличивается (`.food.selected` в `explore-map.module.css`). Заведение, ставшее остановкой, рисуется один раз — меткой остановки.
