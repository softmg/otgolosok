# Загрузка мест на карте по ячейкам 1°

Экран «Рядом», включая создание прогулки, получает места из тонкого индекса. Индекс разбит на ячейки 1°×1°: вся Москва помещается в ячейку `55:37`, а Зеленоград лежит на линии 56° с.ш. Текст истории загружается только при открытии карточки. Предыдущая схема с прямоугольниками и постраничным `GET /api/content/places` больше не используется клиентом. Её API оставлен для совместимости и админки.

## Модель ячеек

Ячейка точки — `(floor(lat), floor(lon))`, ограниченная значениями lat ≤ 89 и lon ≤ 179. Поэтому последняя строка и последний столбец включают верхнюю границу. Нижняя граница ячейки включена, верхняя исключена. Точка с широтой 55,999999 относится к ячейке 55, хотя в ответе её координата округлена до 56,0 (5 знаков, около 1 м).

Точка индекса — `{id, lat, lon, title, address, durationSec, facts, sources}`:
- `title` берётся из последней утверждённой истории, а без неё — из названия места;
- `durationSec` берётся из последней утверждённой озвучки, иначе `null`;
- `facts` и `sources` — количество фактов и источников.

Код модели находится в `backend/map-cells.mjs`.

## API

- `GET /api/content/map-cells` — манифест `{"version":1,"cellSize":1,"cells":[{lat,lon,count,etag}]}`. Самих точек в нём нет.
- `GET /api/content/map-cells/{lat}/{lon}` — ячейка `{"lat","lon","points":[…]}`, точки отсортированы по `id`. Пустая ячейка отдаёт `points: []`.
- `GET /api/content/places/{id}` — деталь места. Формат ответа прежний, теперь с ETag. Ответ 404 приходит с `no-store`.

Проверка запросов строгая: у каждой ячейки ровно один URL и один ключ кеша. Ответ 400 возвращается, если:
- указаны любые query-параметры;
- использован `-0`;
- есть ведущие нули или дробные значения;
- lat выходит за −90…89 или lon за −180…179.

Поддерживаются GET и HEAD.

Кеширование на сервере устроено так (`backend/http-cache.mjs`):
- ETag — первые 32 hex-символа SHA-256 тела. Etag ячейки в манифесте всегда совпадает с ETag её ответа.
- `Cache-Control: no-cache` и `Vary: Accept-Encoding`.
- `If-None-Match` поддерживает список, `W/` и `*`, при совпадении возвращается 304.
- Сжатие: br (качество 5), иначе gzip, иначе без сжатия; `q=0` учитывается. Сжатые тела хранятся в LRU на 32 записи.

## Кеш на клиенте

Хранилище ячеек `mapCellStore` (`src/features/explore/map-cells.ts`) — синглтон модуля, поэтому он переживает размонтирование экрана. Слои кеша:

1. **Память.** Данные хранятся до перезагрузки страницы. Манифест считается свежим `REVALIDATE_MS` = 5 минут. После неудачной перепроверки повтор будет через 30 секунд.
2. **Cache Storage `map-cells-v1`.** Записи создаёт код страницы, Service Worker не меняется. Сохранённая копия показывается сразу, после чего уходит условный запрос с `If-None-Match`. Ошибки хранилища (нет API, приватный режим, квота) считаются пустым кешем. Кеши `map-cells-*` других версий удаляются.
3. **HTTP-кеш браузера.** Он используется только для детали места: запрос с `cache: "no-cache"` перепроверяется по ETag. Дополнительно в памяти есть LRU на 100 историй.

Как загружаются ячейки:
- Запрашиваются только ячейки из манифеста, пересекающие нужную область; касание границы тоже считается пересечением. Остальные ячейки пустые.
- Одновременно загружается не больше 4 ячеек, параллельные запросы одной ячейки объединяются.
- Ячейка повторно скачивается только при смене её etag. Если ETag ячейки новее манифеста, она принимается, а манифест помечается устаревшим.
- Точки всех загруженных ячеек объединяются по `id`, и побеждает последняя полученная ячейка. Поэтому место, перенесённое через линию, не задваивается, а линия ячеек на карте не видна.
- Новый манифест обновляет ячейки для восьми последних запрошенных областей.

Хук `useMapCatalog` запрашивает буферную область карты: два шага отдаления от видимой. Так соседняя ячейка загружается до того, как пользователь до неё дойдёт.
- «Загружаем места…» показывается, только пока у видимой области нет никакой копии данных. Фоновая перепроверка ничего не показывает.
- Радиус «Историй рядом» загружается отдельно. Если он пересекает линию, рекомендации ждут обе ячейки.

Кластеризуются только точки каталога: у них `clusterable: true`. Собственные истории, главы и выбранная точка в кластеры не попадают.

Текст истории загружает `usePlaceStory` (`place-story.ts`). Один запрос на место делится между всеми потребителями. Отмена откладывается на микротаск, чтобы повторный монтаж в StrictMode не отправлял второй запрос. Ответ 404 означает, что история снята с публикации: показывается «Эта история больше недоступна.», и манифест перепроверяется.

## Выкладка

Сначала выкладывается backend, затем frontend. Новый frontend требует новых эндпоинтов, а старый продолжает работать с прежним списком. Индекс `place_texts_place_idx` создаётся при открытии хранилища.

В `docker/nginx.conf` добавлены `location /api/content/map-cells` и `location ~ "^/api/content/places/osm:"` без переопределения `Cache-Control`. Ответы адресуются по содержимому и не содержат личных данных: ячейка — квадрат 1°, а не положение пользователя. Ingress production (Traefik → backend) менять не нужно. Проверка после выкладки описана в [журнале выкладок](../production-runbook.md).

## Замеры (1 октября 2026)

Замер сделан локально на тестовой базе: `seed-osm-test-points.mjs` загрузил 1 743 точки, 1 741 из них в ячейке `55:37` и 2 в `56:37`. Сервер запущен из static export.

| Ответ | без сжатия | gzip | br |
|---|---|---|---|
| Манифест | 183 Б | 147 Б | 128 Б |
| Ячейка `55/37` | 386 342 Б | 66 811 Б | 61 084 Б |

Для сравнения: одна страница прежнего списка из 100 мест весила 132 839 Б без сжатия.

Поведение в браузере (Chromium, 1280×800):
- **Первое открытие:** два запроса — манифест и одна ячейка, передано 61 КБ.
- **Повторное открытие:** один условный запрос манифеста с ответом 304 (300 Б), ячейка берётся из Cache Storage без сети. Маркеры появляются через 2,2 с после навигации, включая инициализацию MapLibre.
- **Клик по месту:** загружается деталь размером около 1,2 КБ.
- Ошибок JavaScript нет.

Если панель браузера Claude скрыта, окно имеет размер 0×0, и карта не сообщает свою область. Перед проверкой нужно задать размер через `resize_window`.

## Проверки

Unit-тесты покрывают:
- backend: модель ячеек, границы ячеек, смену etag после утверждения текста, озвучки и архивации, HTTP-кеш, сжатие и проверку запросов;
- frontend: `cellsFor`, хранилище, Cache Storage, дедупликацию через линию, `usePlaceStory` и `fetchWithRetry`.

Компонентные тесты проверяют экран «Рядом»: радиус через 56° с.ш., повторный монтаж из памяти, ошибку, повтор и режим обслуживания.

Браузерный набор (`e2e/map-catalog.spec.ts` с моками из `e2e/support/map-catalog.ts`) проверяет:
- 1 438 точек ровно двумя запросами;
- пустой каталог;
- ожидание и повтор после 503;
- кластеры;
- отсутствие новых запросов при отдалении на весь город и при повторных циклах приближения и отдаления;
- сохранение карточки при перемещении;
- отрисовку из Cache Storage после перезагрузки без сети.

Полный прогон 1 октября 2026: прошли 488 сценариев. Падают три сценария `прогулка / до старта` (Chromium 320×568 и 390×844 с вырезом, WebKit 320×568). Они так же падают на коде без этой задачи: панель перекрывает маршрут.
