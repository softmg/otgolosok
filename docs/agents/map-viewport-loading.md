# Загрузка мест по области карты

На экране «Рядом», включая создание прогулки поверх этой карты, каталог загружается после определения реальных размеров и положения Leaflet-карты. Первый запрос охватывает прямоугольник после двух нажатий «Отдалить»: при обычном масштабе это четыре ширины и четыре высоты экрана. Границы вычисляются через проекцию карты, с учётом минимального масштаба, сохранённого положения и начального фокуса.

## Догрузка и кеш

События окончания перемещения и изменения размера объединяются задержкой 160 мс. Если область с небольшим запасом (полшага уменьшения масштаба) выходит за полностью загруженный прямоугольник, клиент получает новый прямоугольник с запасом в два шага. Поэтому запрос начинается до появления пустого края. Все страницы выбранной области читаются до конца; весь городской каталог в фоне не скачивается.

Кеш живёт до размонтирования экрана. Полученные места объединяются по ID и сохраняются при перемещении, ошибке и повторе запроса, поэтому открытая карточка не исчезает. Полностью загруженные, в том числе пустые, прямоугольники повторно не запрашиваются. Покрытие проверяется по объединению всех полученных прямоугольников. При расширении области из запроса вычитаются уже загруженные участки: оставшиеся полосы читаются последовательно, а успешно завершённые полосы сохраняются в кеше даже при ошибке или отмене следующей. После успешного завершения полос покрытие объединяется в исходный прямоугольник, чтобы кеш не дробился при каждом изменении масштаба. Границы API включительные, поэтому места ровно на общей границе полос могут повториться в ответах; клиент объединяет их по ID. Незавершённая область не считается покрытой: смена области отменяет запрос, поздние ответы игнорируются. Расширение окна и уменьшение масштаба используют тот же механизм. При отображении всего города запрос закономерно может охватить весь каталог.

«Истории рядом» независимо получают прямоугольник, содержащий весь выбранный радиус 100/200/300 м, затем применяют существующий точный фильтр расстояния. Это сохраняет полноту рекомендаций при перемещении карты и на большом масштабе. До завершения запроса показывается ожидание; при ошибке сохраняются полученные истории и доступен общий повтор загрузки. Прогресс считается по текущим запросам, а не по суммарному числу мест в кеше.

## API и выкладка

`GET /api/content/places` принимает четыре дополнительных числовых параметра: `west`, `south`, `east`, `north`. Передаются все четыре, с возрастающими границами в диапазонах долгот ±180° и широт ±90°. Пустые, повторяющиеся, неполные и некорректные параметры возвращают 400; смешивать прямоугольник с `lat/lon/radius` нельзя. Географический фильтр применяется до подсчёта `total`, `LIMIT` и `OFFSET`, границы включаются. Индекс координат создаётся автоматически при открытии хранилища; старые запросы без прямоугольника остаются совместимыми.

Для выкладки нужно обновить backend до публикации нового frontend: прежний backend отклоняет новые параметры как неизвестные. Ревизия `ec999e8` опубликована 30 сентября 2026 года: сначала backend, затем frontend; результаты проверки и резервные копии приведены в [журнале выкладок](../production-deployment.md).

## Проверки

Unit-тесты проверяют геометрию запаса для телефона и компьютера, минимальный масштаб, границы радиуса, кеш пустых областей, отмену и поздние ответы, неполную загрузку, повтор и прогресс. Компонентные тесты проверяют полный каталог выбранной области, отдельный поиск рядом за её пределами, изменение радиуса и ошибку без ложного сообщения об отсутствии историй. Серверные тесты проверяют фильтрацию, страницы, границы, валидацию HTTP и исключение неутверждённых мест.

Браузерный набор карты проверяет реальный размер первого запроса, догрузку при отдалении и перетаскивании, сохранение выбранной карточки, кластеры, прогресс и повтор после сбоя. Проверки используют ответы API из фикстур; внешние тайлы не являются критерием успешности. Скриншоты телефона и компьютера просмотрены.

Полный браузерный прогон: 412 сценариев прошли. Два сценария Chromium (`прогулка / до старта`, 320×568 и 390×844 с вырезом) выявляют перекрытие маршрута панелью; они повторно воспроизведены в отдельной копии на коде из Git без изменений загрузки каталога. Исправление требует учёта панели при размещении маршрута на экране прогулки; в эту задачу оно не включено. Все 323 сценария WebKit остановились до выполнения: установленный браузер падает при запуске с `Bus error: 10`; для проверки Safari нужно восстановить совместимый WebKit runtime.

Общий линтер рабочего каталога во время проверки остановился на CSS параллельно разрабатываемой админки. Для проверки только этой задачи подготовлена временная копия файлов из Git с наложенными изменениями карты. В свежей копии перед проверками нужны `pnpm exec next typegen` и `node scripts/build-walk-catalog.mjs`: первый создаёт тип `LayoutProps`, второй приводит сгенерированный каталог к ожидаемому формату. Символическая ссылка на внешнюю папку `node_modules` не подходит для Turbopack; зависимости скопированы в копию проекта.

Изолированный `pnpm check` прошёл полностью: 583 frontend-теста, 522 backend-теста, Ruff, Pyright, 19 Python-тестов и 12 subtests, production-сборка. Все 12 сценариев браузерного набора карты прошли; после усиления проверки появления первоначально далёкой точки два сценария телефона и компьютера прошли повторно.

После завершения соседних изменений финальный `pnpm check` в основном рабочем каталоге также прошёл полностью: 589 frontend-тестов, 529 backend-тестов, 19 Python-тестов и 12 subtests, линтеры, типы и production-сборка.

На production в новых сессиях Chromium первая область загрузила 34 места одним запросом на телефоне 390×844 и 217 мест тремя запросами на компьютере 1440×1000 вместо всего каталога из 1 461 точки. Проверены запас в два шага, догрузка при отдалении и перетаскивании, повторное использование кеша и отсутствие ошибок JavaScript; API не подменялся.


## Исправление повторной загрузки при изменении масштаба, 1 октября 2026

Раньше проверка кеша искала один прямоугольник, содержащий требуемую область; при расширении снова запрашивался весь прямоугольник вместе с уже полученными точками. Теперь геометрическое вычитание оставляет только недостающие участки и учитывает совместное покрытие нескольких запросов. Новые тесты проверяют отсутствие пересечения с внутренней частью кеша, отверстия и общие границы покрытия, повторные циклы масштаба, сохранение завершённых полос после ошибки и повтор без их перезагрузки.


Проверка исправления: `pnpm check` прошёл полностью (600 frontend-тестов, 529 backend-тестов, 20 Python-тестов и 15 subtests, линтеры, типы и production-сборка). Все 12 сценариев `e2e/map-catalog.spec.ts` в Chromium прошли, включая повторные циклы масштаба на 390×844 и 1440×1000 без новых запросов в покрытой области. Кеш по-прежнему ограничен временем жизни экрана; перезагрузка страницы начинает новую загрузку.
