# Группировка мест на карте

Каталог объединяется в группы с количеством через [Leaflet.markercluster](https://github.com/Leaflet/Leaflet.markercluster). Радиус группы — 52 экранных пикселя: при приближении точки расходятся, нажатие или Enter приближает группу. Совпадающие координаты раскрываются веером, поэтому каждая история остаётся доступной.

Выбранное место, готовящаяся история и пронумерованные остановки прогулки находятся в отдельном слое. Фоновые точки при создании прогулки группируются. Обновление страниц каталога добавляет только новые маркеры пакетами, удаление проходит через соответствующий слой. Координаты сравниваются с исходными данными: временное смещение маркера при раскрытии веером не должно сбрасываться при повторном рендере React.

Плагин загружается после Leaflet только в браузере. Он расширяет исходный CommonJS-объект, поэтому используется default-export Leaflet, а не неизменяемое пространство имён динамического импорта. Анимация групп отключена в соответствии с мгновенным масштабированием карты; это исключает отложенные анимационные обращения к карте после ухода с экрана.

Группы имеют область нажатия 48×48, число мест и доступное имя с действием. Объекты за пределами расширенной видимой области исключаются из DOM средствами плагина. Полный каталог по-прежнему загружается постранично со статусом и повтором после ошибки: эта оптимизация сокращает число рисуемых элементов, объём ответа API не меняется.

## Проверка

На 1 438 тестовых местах сумма чисел в группах и отдельных маркеров равна 1 438, при исходном масштабе DOM содержит меньше 30 маркеров. Проверены догрузка страниц, изменение координат, удаление мест, выделение, пустой каталог и восстановление после HTTP 503. Отдельные браузерные сценарии проверяют Enter, повторное объединение при отдалении, раскрытие совпадающих координат и открытие карточки.

На production-сборке локально прошли 69 браузерных сценариев карты, интерфейса и прогулок. Скриншоты групп и раскрытых точек просмотрены. Полная проверка `pnpm check` включает линтеры, типы, frontend/backend/Python-тесты и статическую сборку. Первичная версия опубликована 30 сентября; последующее объединение с обновлениями `main` описано ниже.


## Совместимость с обновлениями main

При подготовке выкладки обнаружена разошедшаяся история: локальная кластеризация и полный каталог отсутствовали в `origin/main`, а удалённая ветка уже содержала MapShell, CSS Modules, векторную подложку MapLibre/VersaTiles и новую геолокацию. Выполнено обычное слияние с `1f0d9da`, без замены локальной версии целиком содержимым удалённой ветки. Так сохраняются уже опубликованные изменения backend, исследования и фотографии.

Группы используют CSS Module карты и те же цветовые токены, что и новая оболочка. Оставлены московский предел отдаления, собственные кнопки масштаба, учёт свободного пространства, векторная подложка и растровый fallback. Карточка с фото встроена в StorySheet; прогресс полного каталога — в область уведомлений MapShell. Старые глобальные explore.css, map-dots.css и place-photo.css удалены после переноса стилей.

Входящий diff от общей базы не меняет backend. Файлы stories-only промо-прогулок `content-store.mjs`, `walks.mjs` и `promo-walks.mjs` уже совпадают по SHA-256 с production. Для этой интеграции требуется только выкладка frontend; прямая выкладка backend из origin/main откатила бы более новые локальные изменения исследований.


Проверки объединения: полный `pnpm check` (552 frontend-теста, 495 backend-тестов, 19 Python-тестов и 12 subtests, линтеры, типы, сборка), 71 браузерный сценарий интерфейса/прогулок/навигации, 9 сценариев каталога и 7 сценариев фотографий. В Chromium также прошла матрица из 153 сценариев карты и создания прогулки. Прогресс каталога сохранён и при создании прогулки, несмотря на скрытие остальных уведомлений в этом режиме.

WebKit на macOS 14.3.1 завершает собственный процесс с `Bus error: 10` ещё до открытия страницы (`webkit_mac14_arm64_special-2251`). Простой запуск `about:blank` с чистой локалью воспроизвёл тот же сбой. Результат Safari не подтверждён; эту часть матрицы нужно повторить в совместимом окружении WebKit.
