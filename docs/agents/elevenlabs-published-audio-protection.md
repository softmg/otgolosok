# Защита опубликованной озвучки ElevenLabs

Обычная постановка в очередь сохраняет текущую опубликованную запись ElevenLabs при смене модели, если квитанция успешного задания подтверждает исходный текст и логический голос. Для каталога используется реально выдаваемое аудио, включая запись предыдущей редакции: совпадение текста проверяется отдельно, поэтому старое аудио другого рассказа не блокирует новое задание.

Происхождение записи проверяется по квитанциям и текстовым хешам заданий, а не только по `audio_artifacts.job_id`: разные задания могут получить одинаковые байты MP3. Если голос совпадает, но надёжных данных о тексте нет, обычный запрос получает `CONFLICT`; редактор может использовать «Озвучить заново». Массовое восстановление происхождения или переозвучка не выполнялись.

Явное действие передаёт UUID `requestId`. Его повтор ищется по месту каталога и профилю, включая прежние текстовые редакции: смена модели не создаёт новое задание, смена рассказа или логического голоса даёт конфликт. Повтор завершённого, ошибочного или отменённого запроса возвращает прежнее состояние без автоматического возобновления работы.

В payload явного задания сохраняется `cacheNamespace=external-revoice:<jobId>`. Он остаётся одинаковым при смене lease, попытки и перезапуске. Кеш явного задания ищется с сохранённой моделью и фиксированной версией подготовки `external-revoice-v1`: после смены текущей модели готовый результат повторно публикуется без синтеза. Если готового кеша нет, несовпадение моделей завершает задание ошибкой `TTS_MODEL_MISMATCH` до обращения к провайдеру; для новой модели редактор создаёт новую явную переозвучку. Следующая явная переозвучка получает отдельный namespace; обычные ключи кеша остались прежними. Старое аудио доступно до успешной публикации замены. Ручной повтор старого ошибочного или отменённого задания ElevenLabs отклоняется, если для того же места и профиля уже есть активное задание; допустимый повтор сохраняет исходный ID и namespace. Повтор также проверяет актуальность исходного текста, чтобы устаревшее задание не потратило кредиты на заведомо непубликуемый результат.

Переключение ключей `ELEVENLABS_API_KEYS` не изменено: голос-копия другого аккаунта сохраняет основной логический ID в метаданных. Добавление ключа само по себе не разрешает замену опубликованных записей. Проверки использовали только фиктивные провайдеры и временные базы, без чтения ключей и платных вызовов.

## Проверка

Итоговый `pnpm check` прошёл 5 октября 2026 года: 1536 клиентских тестов, 869 backend-тестов, 26 Python-тестов и 78 вложенных проверок, линтеры, проверка типов и production-сборка. В общем ESLint остались 75 предупреждений прежнего кода; проверка изменённых файлов ошибок не обнаружила.

Регрессионные тесты сначала воспроизвели лишнее задание при v3 → v4 и отсутствие отдельной идентичности явной переозвучки. Локальный HTTP-сценарий использует настоящие `createNarration`, ffmpeg и ffprobe с PCM-фикстурами: публикует v3, перезапускает базу с v4, повторяет утверждение без синтеза, запрашивает новую запись и проверяет старое аудио через административный и публичный API. Сбой после сохранения MP3, перед публикацией, затем перезапуск с v4 Turbo и повтор не вызывают speech повторно; повтор UUID не создаёт задание, следующий UUID на той же модели вызывает свежий синтез.

Гарантии ровно одного списания нет: если процесс завершится после ответа провайдера, но до надёжного сохранения результата, повтор может снова вызвать провайдера. Устранение этого окна требует отдельного протокола с провайдером; в этой задаче добавлена повторная выдача уже сохранённого результата.
