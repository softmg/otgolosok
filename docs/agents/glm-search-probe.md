# Проверка поиска GLM через Airouter, 29 сентября 2026 года

Проверены модели из фактического ответа `GET /v1/models` шлюза
`https://airouter.softmg.tech/v1`: `opencode-go/glm-5.2`, `opencode-go/glm-5.3`
и `opencode-go/glm-5.3-flash`. Контекст взят из трёх существующих неутверждённых
черновиков; база открывалась только для чтения. Тексты, очередь и настройки
провайдеров не менялись.

## Выборка и запрос

| Объект | OSM ID | Контекст |
|---|---|---|
| Российский музей медицины | `osm:node:8664353717` | Большой Николоворобинский переулок, 7 с1; 55.7519588, 37.649217 |
| Мишка с мячом | `osm:node:4142950214` | Музеон, Крымский Вал, 2; 55.7370823, 37.6084488 |
| Башня Татлина | `osm:node:12052845947` | Пресненская набережная, 8 с1; 55.747337, 37.5390827 |

Для каждой пары «объект × модель» отправлен один запрос `/responses`:
`store:false`, `stream:false`, `max_output_tokens:6000`,
`tools:[{type:"web_search"}]`, `include:["web_search_call.action.sources"]`.
Промпт просил сначала выполнить поиск, найти 3–5 надёжных страниц именно об
указанном московском объекте и вернуть прямые URL. Передавались название,
тип объекта, координаты и ближайший адрес; прежние источники модели не показывались.

## Результат

Все девять запросов вернули HTTP 200 и `status:"completed"`, но ни один
не вернул сообщение с ответом, `web_search_call` или пригодные URL.
Модели вызвали функцию `omniroute_web_search` по 2–3 раза; все 20 вызовов
в матрице получили один результат:

```json
{"type":"function_call_output","output":"{\"error\":\"Search provider brave-search returned 422\"}"}
```

| Модель | Музей, с | Мишка, с | Башня, с | Успешных поисков |
|---|---:|---:|---:|---:|
| `opencode-go/glm-5.2` | 12,5 | 6,9 | 5,5 | 0/3 |
| `opencode-go/glm-5.3` | 5,3 | 8,5 | 5,6 | 0/3 |
| `opencode-go/glm-5.3-flash` | 6,6 | 7,5 | 9,9 | 0/3 |

Дополнительно каждая модель получила запрос о Башне Татлина через
`/chat/completions` с `stream:false`, одним пользовательским сообщением и без
`tools` — форма вызова, используемая экспериментальным `searchSources`.
Все три запроса прерваны клиентом по тайм-ауту 90 секунд. Это не доказывает,
что маршрут принципиально не поддерживается: более длительный ответ не проверяли.

Первый предварительный прогон с лимитом 1200 токенов был непоказателен:
часть ответов содержала только reasoning. Повтор с 6000 токенами позволил
увидеть вызовы поиска и общую ошибку Brave; проблема не сводится к малому лимиту.

## Вывод и необходимое исправление

Качество найденных источников сравнить невозможно: поиск остановился на
интеграции шлюза с `brave-search`. Проверенные GLM-модели умеют запросить
этот инструмент, но в текущем состоянии шлюза источников не получают.
Точную причину HTTP 422 и отклонённый параметр ответ шлюза не раскрывает.
Следующий шаг — проверить запрос и настройки Brave в OmniRoute, исправить
ошибку и повторить ту же выборку.

Шлюз также помечает результат с ошибками всех поисковых вызовов как
`completed`. Текущий `backend/provider.mjs` останавливает такой ответ с
`EMPTY_RESPONSE` из-за отсутствия текста; этот код скрывает исходную причину.
Нужно исправить передачу поисковых ошибок и проверить формат успешных
результатов шлюза, прежде чем выбирать GLM для конвейера.

## Платный Hosted web search OpenCode

Это отдельная услуга для подключённых клиентов OpenCode v2. Официальная
[документация Console](https://opencode.ai/v2/docs/console/websearch)
указывает $0.01 за успешный поиск, до восьми результатов; ошибочные запросы
и отказы по лимитам не тарифицируются. Поставщик поиска на этой странице
не назван. Эти условия нельзя автоматически переносить на проверенный
маршрут Airouter → `omniroute_web_search` → `brave-search`.

## Повтор после включения поиска в подписке

29 сентября пользователь сообщил, что включил возможность поиска в подписке.
После этого повторена вся матрица из девяти запросов `/responses` с теми же
промптами и параметрами. Все ответы снова имели HTTP 200 и `completed`,
но все 20 вызовов `omniroute_web_search` вернули
`Search provider brave-search returned 422`. Источников и текстовых ответов нет.

| Модель | Музей, с | Мишка, с | Башня, с | Успешных запросов с источниками |
|---|---:|---:|---:|---:|
| `opencode-go/glm-5.2` | 8,3 | 6,6 | 12,8 | 0/3 |
| `opencode-go/glm-5.3` | 8,4 | 4,7 | 10,3 | 0/3 |
| `opencode-go/glm-5.3-flash` | 30,2 | 32,7 | 6,6 | 0/3 |

Дополнительный запрос о музее через `/chat/completions` для
`opencode-go/glm-5.3`, с `tools:[{type:"web_search"}]` и `max_tokens:6000`,
вернул HTTP 200 за 5,8 секунды. В нём `finish_reason:"tool_calls"`, пустой
`message.content`, два вызова `omniroute_web_search` и два элемента
`tool_results` с той же ошибкой Brave 422.
Контрольный запрос той же модели о музее без `tools` и без ограничения
`max_tokens` прерван по тайм-ауту 120 секунд, как и прежние запросы без инструмента.

Вывод относится к проверенному маршруту Airouter: включение поиска в подписке
не изменило используемый им инструмент. Работу Hosted web search внутри
самого клиента OpenCode этот прогон не проверяет. Для использования поиска
в конвейере нужно исправить интеграцию Brave или отдельно подключить нужный
поисковый сервис к шлюзу; настройки в рамках проверки не менялись.
