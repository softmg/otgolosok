# Контекст OSM для поиска источников

Актуализация 22 сентября 2026 года: добавлен [полный адресный индекс OSM](offline-osm-geocoding.md). При наличии `osm-addresses.sqlite` геометрические адресные ориентиры имеют приоритет над описанным ниже небольшим каталогом; он остаётся вариантом для запуска без индекса.

Дата: 2026-09-18.

`backend/osm-context.mjs` формирует поисковые варианты из названия, типа, альтернативных названий и адресных тегов. Поиск и проверка фактов получают одинаковый контекст. Исходное название каталога сохраняется: для `historic=memorial` без подтипа слова «памятник», «мемориальная доска», «бюст» и «памятный камень» используются как поисковые гипотезы. Инициалы автоматически не раскрываются; идентификаторы изображённого человека отделены от идентификаторов самого объекта.

Полный адрес передаётся отдельно от улицы без номера дома. Если собственного адресного ориентира нет, запросы дополняются адресами максимум двух разных соседних зданий в пределах 300 метров по прямой между координатами объектов. Это ориентиры, а не установленный адрес памятника или доказательство его принадлежности музею. Геометрическое вхождение в здание и расстояние до его границы здесь не проверяются.

Соседние здания берутся из существующего `backend/walk-discovery-catalog.mjs`; сетевых обращений к Nominatim нет. Каталог содержит выбранные примечательные здания, а не все адреса Москвы, поэтому отсутствие соседей не означает отсутствие адресов поблизости. Для расширения покрытия правильное продолжение — извлекать адресные здания и улицы из полного PBF; расширять радиус и назначать дальний адрес самому объекту нельзя. Текущий импорт достопримечательностей сохраняет `addr:street` и `addr:housenumber`; поддержка дополнительных адресных полей в обработчике сама по себе не добавляет их в старый снимок.

Проверка на локальной базе:

- `osm:node:13259774522`, «Г. Галилею»: собственного адреса и подтипа нет; ориентиры — Романов переулок, 2/6 с2 (76 м), Староваганьковский переулок, 23 с1 (78 м).
- `osm:node:4646606685`, «Подводный обитаемый аппарат „Аргус“»: ориентир — Государственный геологический музей им. В. И. Вернадского, Моховая улица, 11 с11 (15 м).
- `osm:node:13972491275`, «Композиция №1»: `tourism=artwork`, адреса и соседних зданий в этом каталоге нет; запрос получает тип «арт-объект», Москва и исходные координаты в контексте.
- `osm:way:96660179`, «Сквер на набережной Шитова»: сохранённая редактура отклонила неподтверждённое утверждение о границах сквера и двусмысленное местоимение, смешивающее мост с берегами пруда. Это отдельная проблема текста, обогащение названия не гарантирует её исправления.

Регрессионные тесты сначала воспроизвели отсутствие расширенных запросов и адресных ориентиров. Проверены импорт → поиск → проверка фактов → сохранение текста с подставным провайдером, отказ при неподтверждённой идентичности, частичные адреса, неизвестные типы и исключение дальних/некорректных соседей. `npm run lint`, `npm run typecheck`, `npm test` проходят: 189 тестов интерфейса и 196 тестов сервера. Живые платные запросы и повторная генерация этих четырёх объектов не запускались.

Чтобы применить новый поиск к отклонённому заданию после обновления сервера, повторить его с `restartFrom: "research"`: обычный повтор может использовать старый исследовательский checkpoint. Автоматической перегенерации опубликованного контента это изменение не запускает.
