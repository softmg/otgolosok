# Отзывы к прогулкам

Отзыв — обязательная оценка 1–5 и необязательный текст до 1000 символов (кодовых
точек Unicode после нормализации). Оставить его можно к каталожной прогулке, к
прогулке по общей ссылке (включая промо) и к своей прогулке из аккаунта. Локальные
гостевые прогулки (`?local=`) отзывов не принимают: сервер о них не знает.

## Данные

Таблица `walk_reviews` лежит в `auth.sqlite` рядом с `user` и `user_walks` и
создаётся в `backend/walk-reviews.mjs` при старте (`CREATE TABLE IF NOT EXISTS`).

- Цель отзыва: `walk_kind` (`catalog` или `account`) и `walk_id` (slug каталога или
  UUID записи `user_walks`). Цель всегда определяет сервер; клиент только называет
  маршрут API. Для общей ссылки и своей прогулки цель одна — UUID прогулки, поэтому
  отзывы видны и владельцу, и по ссылке.
- Автор: `user_id` (каскадно удаляется вместе с аккаунтом) или `guest_key_hash` —
  SHA-256 от ключа устройства. Ровно одно из двух заполнено. Сырой ключ и IP не
  хранятся и не логируются.
- Один отзыв на пару «прогулка + аккаунт» или «прогулка + ключ устройства»
  (частичные уникальные индексы). Повторная отправка обновляет отзыв.
- Внешнего ключа на `user_walks` нет: отзывы переживают удаление прогулки и
  отключение ссылки, в админке остаются со снимком названия (`walk_title`).
  Повторное включение той же ссылки возвращает их на страницу.

## Модерация

`nextReviewStatus(previous, text)`:

| Было | Новый текст | Стало |
|---|---|---|
| — | пустой | `published` |
| — | есть | `pending` |
| `hidden` | любой | `hidden` (решение редакции сохраняется, автор может только удалить) |
| `pending`/`published` | пустой | `published` |
| `published` | тот же | `published` (изменилась только оценка) |
| иначе | — | `pending` |

Итог («★ 4,6 · 12 оценок») считает только `published`. В публичном списке — только
опубликованные отзывы с текстом, новые сверху, курсор по `(created_at, id)`.
Скрытие редакцией убирает и оценку из среднего. Автор видит свой отзыв (`mine`) с
любым статусом.

## API

- `GET /api/story-walks/:slug/reviews`, `GET /api/story-walks/shared/:token/reviews`,
  `GET /api/me/walks/:id/reviews` — `{summary, reviews, nextCursor, mine}`;
  единственный параметр — `cursor`.
- `PUT …/reviews/mine` `{rating, text?}` → `{mine, summary}`; `DELETE …/reviews/mine`
  → `{mine: null, summary}` (идемпотентно).
- Неизвестная, приватная, отозванная, повреждённая или чужая прогулка — одинаковый
  404 `NOT_FOUND`.
- Публичные PUT/DELETE сами проверяют `Origin` и `Sec-Fetch-Site` (общий same-origin
  фильтр сервера покрывает только POST), при сессии — `X-CSRF-Token`. Маршруты
  `/api/me` защищены общим блоком аккаунта.
- Гость передаёт ключ в `X-Review-Key`; без ключа запись отвечает 400
  `REVIEW_KEY_REQUIRED`, неверный формат — 400.
- Редакция: `GET /api/story-admin/reviews?status&rating&q&limit&offset` (неизвестные
  и повторные параметры — 400; `pending` — общее число на модерации),
  `POST /api/story-admin/reviews/:id/moderate {action: "publish"|"hide"}`,
  `POST /api/story-admin/reviews/:id/delete {}`. Строка содержит `walk.url` — ссылку
  на прогулку, пока она доступна, иначе `null`.

Код маршрутов — `backend/walk-review-routes.mjs`, подключён в `server.mjs` тремя
вызовами (`reviews.public/own/admin`).

## Ключ устройства и клиент

- `otgolosok:review-key:v1` — 32 случайных байта в base64url, создаётся при первой
  записи. Гость управляет отзывом только из того же браузера; если хранилище
  недоступно, форма предлагает войти.
- «Оставить отзыв» и «Оценить прогулку» видны всегда, без старта прогулки: фильтр
  «сначала начни прогулку» убран как непонятный пользователям (сервер его и так не
  проверял). Ключ `otgolosok:walk-reviews:started:v1` больше не пишется; у тех, кто
  успел его получить, он просто лежит в `localStorage`.
- Форма оценки открывается отдельным модальным окном (`ReviewDialog`, нативный
  `<dialog>`), а не в шторке прогулки; в шторке «Отзывы» — только итог и список.
  Окно закрывается крестиком, Escape, кликом по фону и кнопкой «Готово» после отправки;
  форма монтируется заново при каждом открытии, чтобы подхватить черновик.
- Пока опубликованных оценок нет, кнопка «Отзывы» в карточке прогулки называется
  «Оставить отзыв» («Изменить отзыв», если свой отзыв ждёт модерации) и сразу
  открывает окно.
- На экране «Прогулка завершена» главная кнопка — «Оставить отзыв» («Изменить отзыв»,
  если отзыв уже есть), она открывает окно; «На карту» — второстепенная. У локальных
  прогулок без отзывов главной остаётся «На карту».
- Черновик неудачной отправки хранится в `otgolosok:walk-reviews:draft:v1:<цель>` и
  подставляется в форму при следующем открытии.
- Любой сбой загрузки отзывов (сеть, схема ответа) показывает «Отзывы сейчас
  недоступны» и не ломает прогулку.
- `loadJson` не повторяет 429, если `Retry-After` больше 5 секунд: ошибка сразу
  показывается пользователю.

## Ограничение записей

20 записей (PUT + DELETE) в час на аккаунт (`user:<id>`) или, для гостей, на IP
(`ip:<X-Real-IP>`). Окно скользящее, отклонённые запросы бюджет не тратят, сверх
лимита — 429 `RATE_LIMITED` с `Retry-After`.

Ограничения: счётчик живёт в памяти процесса и сбрасывается при перезапуске, не
делится между несколькими процессами backend. Гости за одним NAT/CGNAT или за
дополнительным прокси без проброса `X-Real-IP` делят общий лимит. Число ключей
ограничено 10 000: сначала удаляются ключи без записей в окне, затем самый старый.

## Приватность

Публично показывается только имя аккаунта (`user.name`, при пустом — «Пользователь»)
или «Гость»; форма заранее говорит, под каким именем выйдет отзыв. Email виден только
редакции. IP не хранится. Удаление аккаунта удаляет его отзывы.
