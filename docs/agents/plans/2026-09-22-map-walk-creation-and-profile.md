Status: implemented 2026-09-22 in branch `feat/auth-account-osm-pipeline`.

> План — снимок на дату создания. Раздел «Проверенные факты о коде» описывает исходное состояние и может устареть. Перед использованием проверить факты по актуальному коду; это не текущая архитектурная документация.

## Результат реализации

Создание перенесено на карту, добавлены отдельный финиш, история, новая оболочка
профиля и общий размер знака. Старый компонент конструктора удалён. Проверки и
ограничения зафиксированы в [заметке реализации](../map-walk-creation.md).

Уточнения реализации: состояние открытия принадлежит URL, reducer управляет шагом
и выбором на карте, активное поле хранится в hook. Отдельного полноэкранного поиска
нет: адрес выбирается внутри немодальной панели, поэтому focus trap не нужен.
Общие небольшие контролы используют scoped CSS в `features/ui/surfaces.css`;
React-обёртки над нативными кнопками/полями не добавлялись. Исторический CSS
конструктора оставлен на диске из-за независимых пользовательских изменений,
но удалённый компонент его больше не импортирует. Миграция backend требует
обновления до клиента; деплой не выполнялся.

## Контекст

Пользователь хочет цельный современный интерфейс вместо отдельных несогласованных экранов. Создание прогулки должно происходить поверх карты: от выбранного дома либо через пункт «Прогулка» в нижнем меню. История прогулок получает собственный пункт навигации. Профиль перестаёт быть длинной смесью настроек, запросов и списков.

Работа включает переработку интерфейса и полноценную поддержку выбранного финиша. Существующие сохранение, авторизация, генерация историй, проигрывание и офлайн-доступ остаются рабочими. Новый внешний сервис не требуется: используются существующие GET `/api/story-place`, POST `/api/walk-plan`, `/api/walk-research-jobs`, `/api/story-jobs` и `/api/me/*`. Пешеходный маршрут строится через настроенный `WALK_ROUTER_URL`; источник кандидатов задаётся `WALK_DISCOVERY_SOURCE`, Overpass — `WALK_OVERPASS_URL`. Стоимость генерации определяется текущими провайдерами и из исследованного кода не устанавливается; открытие панели и просмотр истории не должны запускать платную генерацию.

## Согласованные решения

1. На карточке выбранного дома действие «Создать прогулку отсюда» открывает создание поверх текущей карты с заполненным стартом.
2. Пункт нижнего меню «Прогулка» сразу открывает окно «Откуда / Куда». Отдельная страница конструктора больше не является пользовательским сценарием создания.
3. В нижнем меню появляется «История» со списком прогулок.
4. Два режима построения: к выбранному месту и автоматическая прогулка на 30/60/90 минут.
5. Сохраняется текущая семантика времени: бюджет ходьбы, без нового расчёта общей продолжительности с прослушиванием. В интерфейсе явно писать «мин пешком».
6. Для автоматической прогулки возврат к старту включён по умолчанию; пользователь может его выключить. Для маршрута к месту финиш задан самим пользователем, переключатель возврата не применяется.
7. Пользователь поручил визуальные решения исполнителю и разрешил полностью заменить текущий интерфейс ради современного, красивого и production-ready результата.
8. Логотип должен выглядеть одинаково на всех страницах.

## Проектные решения в рамках делегированного дизайна

Это решения автора плана, а не отдельные ответы пользователя.

- Нижняя навигация: «Рядом», «Прогулка», «История», «Профиль». Первые два пункта используют одну карту; активный пункт определяется также состоянием панели.
- Главная остаётся картой. История живёт по `/history`, профиль — по существующему `/account`; `/walk` сохраняет просмотр документов и совместимость старых ссылок.
- Стиль: светлые нейтральные поверхности, тёмный читаемый текст, глубокий зелёный основной акцент, ограниченный терракотовый акцент бренда. Manrope — интерфейс; Cormorant — логотип и редкие редакционные заголовки. Без декоративных градиентов, вложенных карточек и множества конкурирующих кнопок.
- Одинаковый компонент шапки и логотип фиксированного размера 28 px во всех пользовательских шапках, без растяжения и наследования размера страницы. Допустим контрастный цвет букв на тёмной поверхности; начертание, пропорции и точка едины. Значок PWA сохраняется отдельным компактным знаком.
- Телефон: нижняя панель с компактным и развёрнутым состояниями. Компьютер: плавающее окно у края карты. Карта остаётся видна и используется для выбора точек; не переносить длинную старую форму целиком внутрь попапа.
- Вход в создание показывает «Откуда» и «Куда» с альтернативой «Погулять по времени». Геолокация — только по явному действию. Старт с карточки дома уже подтверждён, повторное подтверждение не требуется.
- В режиме к месту сохраняется существующий бюджет ходьбы с выбором 30/60/90 минут, по умолчанию 30. При невозможности уложиться предложить изменить бюджет или финиш; не увеличивать время молча.
- История означает сохранённые прогулки и черновики, а не доказанный журнал пройденных маршрутов. Не вводить «Пройдено», статистику километров или даты завершения без реальных данных.
- Название заполняется автоматически и редактируется во второстепенном действии. Настройка остановок доступна из предпросмотра. Подготовка историй запускается отдельным явным действием с сохранением действующих согласия, квот и авторизации.

### 3. Отдельный финиш и надёжное построение

- Добавить `destination?: Place | null` к `Draft`, `ResearchRequest`, `WalkDocument` версии 2 и соответствующим backend typedef/валидаторам. Отсутствие поля в старом документе означает прежнее поведение; новые документы могут хранить null. Выбранный финиш допустим только при `mode: open`.
- Обновить `backend/walk-document.mjs`, `src/features/walks/model.ts`, `adapters.ts`, `src/features/walk-builder/model.ts` и проверки в loader/offline, где используется схема. Старые документы и каталог не переписывать массово; проверить полный цикл сохранение → загрузка → редактирование → shared view → офлайн.
- Контракт планировщика: `planWalk({ start, destination?, mode, minutes, stops? }): Promise<Plan>`. При наличии финиша геометрия строится `start → stops → destination`; конечная точка не может исчезнуть при сокращении остановок и не обязана иметь исторический материал.
- В `backend/walks.mjs` разрешить маршрут к финишу без промежуточных исторических остановок. Для этого сценария ноль остановок — корректный маршрут, но не обещание готовой аудиоэкскурсии. Соответственно обновить `isPlan`, `validStops` и условие route/stops в валидаторе документа; прежние правила маршрута без финиша не ослаблять.
- Для автоподбора к месту искать кандидатов вдоль направления старта и финиша в пределах действующего бюджета; финальное решение принимает пешеходный router. Ограничить число кандидатов и попыток, не обещать оптимальный маршрут. Сначала проверить достижимость самого финиша. Убирать можно только необязательные остановки; ручной порядок не менять молча.
- Проверять одинаковые/слишком близкие точки, координаты вне поддерживаемой области, невозможный бюджет и маршрут без пешеходного пути. Возвращать короткие различимые сообщения; не рисовать прямую линию вместо реального маршрута.
- В `backend/walk-research.mjs`, `walk-research-store.mjs`, обработчиках `backend/server.mjs`, `ResearchPanel` и клиентских `researchKey/researchLookup/researchMatches` протянуть финиш. Старые запросы без финиша сохраняют старую идентичность; запросы с финишем включают нормализованные координаты в ключ и recovery lookup. Не смешивать старые задания с новыми.
- Передавать финиш через все фазы исследования и итоговый маршрут. Истории генерируются только для выбранных исторических остановок, не автоматически для каждой точки A/B.
- Сохранить ограничения размера ответа, таймауты, проверку геометрии, квоты и consent. Новые сетевые операции повторять с ограниченным exponential backoff только для сети/429/5xx в рамках общего deadline; не повторять deterministic 4xx. Мутации и задания — только с тем же idempotency/recovery key. Развёртывание схемы: backend с поддержкой нового поля перед новым клиентом.

## Тестирование и критерии приёмки

- Unit: reducer панели, URL и Back/forward, старые и конфликтующие ссылки, переключение A/B ↔ время, default loop, восстановление и отсутствие перезаписи чужого черновика. Проверять результат и состояние, не только вызов mock.
- Данные: старый документ без destination, новый с финишем, roundtrip адаптеров, локальное/аккаунтное хранение, shared view, офлайн, старые recovery keys, разные финиши дают разные новые keys. Конфликт revision не затирает данные.
- Backend: пешеходный A/B с остановками и без, недостижимый финиш, совпавшие точки, выход за границы, превышение бюджета, удаление только необязательных остановок, сохранение конечной точки при исследовании, таймаут/429/5xx/4xx и отмена. Существующие loop/open тесты остаются зелёными. Внешние API в автоматических тестах заменены фикстурами; платные вызовы запрещены.
- История/профиль: пустые состояния, гостевой режим, две страницы аккаунтных данных, частичный отказ, недоступное хранилище, честные статусы, сохранение имени, sharing и отзыв, выход и очистка приватных материалов.
- Добавить исполняемые браузерные регрессии через минимальную dev-зависимость Playwright и `test:e2e`, если другой runner к началу реализации не появился. Fixtures должны перехватывать внешние API; не использовать реальные пользовательские записи и платную генерацию. Исключить временные отчёты из git.
- E2E: нажать дом → «Создать прогулку отсюда» → старт заполнен; «Прогулка» с карты/истории/профиля → панель на карте; выбрать A/B или 30/60/90; посмотреть маршрут, сохранить, закрыть, открыть из истории, редактировать, слушать готовые части. Проверить refresh, Back/forward и восстановление серверного задания без повторного заказа.
- Браузер: 360×800, 390×844, 768×1024, 1440×900, короткие 568×400 и 844×390; соседние ширины каждого изменённого breakpoint. Проверить реальную геометрию панели, safe-area, клавиатуру поиска, отсутствие перекрытий CTA/навигации/атрибуции, scroll, focus, Escape, reduced motion и контраст. Размер логотипа сравнить computed styles и скриншотами всех шапок.
- Выполнить `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm test:e2e` после добавления runner и `pnpm build`; проверить экспорт `/history` и совместимость nginx/service-worker с новым путём, не предполагать её автоматически.
- Финальное свидетельство: скриншоты карты с панелью, истории и профиля на мобильном/desktop, пройденные команды, коммиты и явно названные непроверенные внешние зависимости. Успешная сборка не заменяет браузерную проверку и не означает деплой.
